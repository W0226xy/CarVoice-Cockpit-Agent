# 产品范围

## 项目背景与目标

车语智舱 Agent 是面向 Android 车机/车机模拟器的智能座舱实习项目。目标是验证一套可演进、可审计且安全隔离的 Agent 架构，使用户能够用自然语言查询模拟车辆状态、发起座舱操作、设置导航、控制媒体并查询车辆手册。

第 1 阶段只建立基础工程、边界和契约，不交付可用的智能对话或车辆控制能力。

## 首期 MVP 功能

- Android 车机端提供文本会话界面、连接状态和工具执行进度展示；
- Ktor 服务通过 WebSocket 接收会话请求并流式返回文本或工具状态；
- Koog 负责编排对话和选择已注册工具，不直接访问车辆接口；
- `MockVehicleTool` 查询并修改内存中的模拟车辆状态；
- 提供模拟空调、车窗、导航和媒体操作；
- 对高风险操作执行参数校验、权限校验、二次确认和审计；
- 基于可追溯手册片段回答车辆知识问题；
- 网络错误、拒绝执行和服务不可用时给出明确反馈。

## 明确不做

- 不连接真实 Vehicle HAL、CAN 总线、ECU 或物理车辆；
- 不实现自动驾驶、驾驶决策、远程车辆控制或后台静默控制；
- 不允许大模型绕过工具注册表直接执行操作；
- 不存储或提交真实 API Key、账号、Token 和数据库密码；
- 首期不承诺量产级 ASR/TTS、离线大模型、多车多租户和车规认证；
- 第 1 阶段不实现 WebSocket、Koog、Mock 工具逻辑、语音、RAG、数据库或缓存。

## 典型使用场景

1. 用户询问“当前车内温度和剩余续航是多少”，系统读取模拟状态并展示结果。
2. 用户说“把空调调到 23 度”，系统校验参数后修改模拟空调状态。
3. 用户要求“打开驾驶位车窗”，系统识别为高风险执行，展示参数并等待确认。
4. 用户说“导航到上海虹桥站”，系统启动模拟导航并返回目的地与状态。
5. 用户说“播放下一首”或“暂停音乐”，系统更新模拟媒体状态。
6. 用户询问“胎压报警灯亮了怎么办”，系统返回带来源的车辆手册答案。

所有“执行”均指模拟状态变化，不代表真实车辆行为。
